2. TARGET PERSONAS & USER JOURNEYS
================================================================================
1. Autonomous Multi-Agent Swarm Engineers & Orchestrators
   - Need: Deterministic, non-overlapping execution scheduling for LLM agent loops, periodic memory compaction, and scheduled evaluations.
   - Pain Point: Heavy cloud brokers (Celery, Celery Beat, Redis Queue) create complex ops overhead; cron does not provide atomic run deduplication or distributed worker lease guarantees.
   - Solution: ellmos-scheduler provides atomic SQLite lease claiming, content-addressed deterministic run_id generation, and clean failure tracking.

2. Local-First & Zero-Egress Tool Builders
   - Need: 100% offline, local-only daemon and CLI task scheduler without telemetry or cloud phone-home mechanisms.
   - Pain Point: Most modern scheduling solutions rely on cloud APIs, SaaS control planes, or leak telemetry across network interfaces.
   - Solution: Complete zero-egress guarantee (INV-LOCAL-01), operating strictly on local SQLite state databases in user space.

3. DevOps & Site Reliability Engineers
   - Need: Rock-solid, cross-platform job scheduler that works reliably across Windows, Linux, and macOS without brittle cron differences.
   - Pain Point: Windows Task Scheduler and Linux cron have disparate semantics; Windows Python environments often lack IANA time zone data (`Europe/Berlin`).
   - Solution: Identical cron/interval/daily semantics across all 3 platforms with bundled `tzdata` fallback on Windows.

4. Enterprise Compliance & Security Auditors
   - Need: Verifiable preflight authority enforcement and cryptographic execution proofs before running sensitive jobs.
   - Pain Point: Cron jobs execute scripts blindly without validating if preconditions, approval decisions, or security policies are intact.
   - Solution: Dual read-only passes + SHA-256 authority preflight (`--require-authorities`) and immutable cryptographic execution receipts.

5. 10 GOVERNANCE & RUNTIME INVARIANTS MATRIX
================================================================================
- INV-LOCAL-01: 100% Local-First & Zero-Egress (System Architecture)
  Operates completely offline on localhost; strictly zero telemetry, analytics, external network sockets, or unauthorized cloud beacons.
- INV-PRIV-02: Unprivileged Non-Elevation Execution (Security Boundary)
  Executes strictly in unprivileged user-mode (RunAsInvoker), never requiring administrative, root, or elevated privileges.
- INV-CONC-03: Atomic SQLite Leases & Deduplication (Concurrency Control)
  Deterministic, content-addressed run_id generation and atomic SQLite state leases prevent parallel double-execution across workers.
- INV-AUTH-04: Double Read-Only Authority Preflight (Integrity Guard)
  Mandatory authority files are read twice and validated against cryptographic SHA-256 integrity checksums prior to job dispatch.
- INV-STRM-05: Strict UTF-8 & Fail-Closed Decoding (Stream Hygiene)
  Subprocess output decoding enforces strict error handling (utf-8:strict), terminating corrupted outputs cleanly instead of corrupting audit logs.
- INV-EXEC-06: Shell-Free Safe Process Invocation (Execution Security)
  Process invocations accept explicit argv lists only, completely avoiding shell string interpolation (shell=False).
- INV-RES-07: Fail-Closed Timeout & Abandoned Leases (Process Resilience)
  Overdue, hanging, or crashed workers have their leases marked abandoned and reclaimed safely without deadlocks.
- INV-MOD-08: Declarative Modular Integration (Decoupled Architecture)
  Pluggable executor registry, external authority resolvers, and clean decoupling outside monoliths (e.g. BACH).
- INV-PLAT-09: Multi-OS Cross-Platform Parity (Platform Portability)
  Complete operational parity on Windows (with tzdata fallback for IANA time zones), Linux, and macOS.
- INV-SLA-10: Cryptographic Receipt Persistence & Security SLAs (Auditability & Maintenance)
  Full audit records with immutable receipts, SHA-256 authority sets, 48h initial response and 5 business days triage security SLAs.
